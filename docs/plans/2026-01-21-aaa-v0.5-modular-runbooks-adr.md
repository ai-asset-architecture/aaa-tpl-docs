# AAA v0.5 Modular Runbooks ADR

## Background & Motivation
v0.5 的核心目標是建立可組合、可驗證、可重放的 Multi-repo Runtime，讓 v0.4 的治理規則真正落地為自動化執行層。現況的 `aaa init` 仍偏單體黑盒，任何失敗都放大治理成本，且對 Agent/CI 不友善。為了讓 Pipeline 能穩定重試與追溯，我們必須將流程拆成原子 Runbook，並以統一 Schema 描述輸入/輸出/錯誤邏輯。這不是單純的工程拆解，而是將流程升級為可治理的資產（Runbook as Code）。

此 ADR 的決策前提是三個原則：
- **Atomicity**：每個 Runbook 只做一件事
- **Idempotency**：可重複執行且狀態一致
- **Uniform Interface**：統一欄位 + 可觀測事件

這些原則是 v0.6 Agent Safety 的必要前置條件，也是後續 `aaa-actions` 自動化管線的邏輯基石。

---

## Architecture & Responsibilities
v0.5 明確區分兩層：**Runbook Definition** 與 **Runtime Engine**。Definition 層產出標準化 Runbook（Schema + step definitions），包含 `inputs`、`preconditions`、`steps`、`outputs`、`error_codes`，以及安全/可觀測欄位。這層是治理資產，應獨立版本化並可被 lint / eval 靜態驗證。Runtime 層（`aaa-tools`）只負責解釋並執行 Runbook，確保流程可重放與錯誤可控，不再承擔規則設計責任。

在 repo 分工上：
- `aaa-tools`：runtime 與 runbook 定義
- `aaa-evals`：runbook schema validation 與一致性檢查
- `aaa-actions`：標準化 pipeline 觸發，輸出報告至 `aaa-tpl-docs/reports/`

此外加入 **Runbook Registry/Discovery** 機制：Runtime 支援 `runbook_id@version` 解析與遠端載入，並透過 checksum/signature 驗證資產來源，確保 Agent 呼叫的是「被授權版本」。

---

## Runbook Schema: Fields & Behavior
Runbook Schema 分三層：**Identity/Discovery**、**Execution Contract**、**Observability & Safety**。

### Identity/Discovery
- `runbook_id`
- `version`
- `source`
- `checksum`
- `requires_engine`

用途：支援 registry 下載與版本鎖定，避免舊引擎誤執行新語法。

### Execution Contract
- `inputs`
- `preconditions`
- `steps`
- `outputs`
- `error_codes`
- `required_scopes`
- `timeout_seconds`
- `idempotency_check`

用途：讓 Runtime 執行前可做權限預檢、限制掛起風險，並以狀態檢查確保冪等性。

### Observability & Safety
- `emit_events`
- `audit_artifacts`
- `failure_modes`
- `declared_side_effects`
- `trace_context` (由 Runtime 注入)

用途：確保每個 step 可追溯並具風險宣告，支援跨 runbook 的 audit 串接。

### Extensibility
- `extensions`

用途：為未來 rollback、interactive、retry policy 等行為保留擴充空間。

## Appendix: Schema Preview (YAML)

```yaml
metadata:
  id: "aaa-ops/init-repo"
  version: "1.0.2"
  checksum: "sha256:..."
  requires_engine: ">=0.5.0"

contract:
  required_scopes: ["repo:write", "org:read"]
  timeout_seconds: 60
  inputs:
    - name: "repo_name"
      type: "string"
      validation: "^[a-z0-9-]+$"
  outputs:
    - name: "repo_url"
  idempotency_check:
    command: "gh repo view {{inputs.repo_name}}"
    expect_exit_code: 0

steps:
  - name: "create_remote"
    action: "gh_cli"
    args: ["repo", "create", "{{inputs.repo_name}}"]

observability:
  declared_side_effects: ["create_github_repo"]
  failure_modes:
    - code: "AUTH_FAIL"
      recoverable: false
    - code: "NETWORK_TIMEOUT"
      recoverable: true
```
