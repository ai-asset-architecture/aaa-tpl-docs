# AAA v0.8 Marketplace Assets Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver marketplace asset packs with a registry index, repo-local installation, and pack-driven checks.

**Architecture:** Add a registry index JSON and a pack manifest schema, then extend `aaa-tools` with pack build/install/list and update repo checks to load pack-provided checks from `.aaa/packs/`. Use repo-local packs to avoid global contamination and allow per-repo versions.

**Tech Stack:** Python, JSON, GitHub releases, YAML runbooks, existing `aaa-tools` CLI.

---

## Plan Summary (200-300 words)

v0.8 transitions AAA from a monolithic governance bundle to a marketplace of asset packs. The plan focuses on three layers: pack format, registry protocol, and installation workflow. We standardize a `pack.manifest.json` describing pack id, version, content paths, and compatibility. Packs are built as zip/tar artifacts and published via GitHub releases. A new registry repo provides a single `registry_index.json` with pack metadata and versioned download URLs. The CLI adds a minimal `aaa pack` group to list available packs, install a pack into `repo_root/.aaa/packs/`, and verify installed versions. We keep scope small: public registry only, no auth or billing. Repo checks are updated to load check scripts dynamically from `.aaa/packs/*/checks/`, enabling pack-delivered governance such as agent safety or DLP. Installation is repo-local to avoid cross-repo pollution and allow per-repo version pinning. Success is measured by deterministic installs and repeatable CI: `aaa pack install agent-safety@1.0.0` should yield a fixed filesystem tree and a registry entry for traceability. We will document the registry protocol and pack structure in `aaa-tpl-docs` and keep `aaa-tools` core lean by shipping templates and evals as packs. Out of scope: private registry auth, payments, or a UI marketplace. The plan is task-driven, test-first, and uses frequent commits to isolate regressions.

## Schema (200-300 words)

Two schemas define the system. First, `registry_index.json` in the registry repo root:

```
{
  "version": "1.0",
  "generated_at": "2026-01-24T00:00:00Z",
  "registries": {
    "official": {
      "type": "github-public",
      "url": "https://raw.githubusercontent.com/.../registry_index.json"
    }
  },
  "packs": {
    "agent-safety": {
      "latest": "1.0.0",
      "versions": {
        "1.0.0": "https://github.com/ORG/registry/releases/download/agent-safety-v1.0.0/agent-safety-1.0.0.zip"
      },
      "requires": ["aaa-tools>=0.8.0"],
      "applies_to": ["agent", "genai-service"]
    }
  }
}
```

Second, `pack.manifest.json` inside each pack:

```
{
  "id": "agent-safety",
  "version": "1.0.0",
  "description": "Safety checks and rules",
  "content": {
    "checks": ["checks/*.py"],
    "rules": ["rules/*.yml"],
    "templates": ["templates/**"],
    "exclude": [".git/**", "__pycache__/**", "tests/**"]
  },
  "requires": ["aaa-tools>=0.8.0"],
  "applies_to": ["agent", "genai-service"],
  "signature": "sha256:..."
}
```

The install path is repo-local: `.aaa/packs/<pack-id>/<version>/`. The CLI should record an `installed.json` ledger under `.aaa/packs/` with id, version, source URL, checksum, and installed timestamp. Repo checks should load all `checks/*.py` found under installed packs, then filter by `applies_to` and repo_type. Pack checks must be namespaced as `<pack-id>::<check-id>` to avoid collisions. Schema validation is minimal in v0.8: JSON parse, required keys present, and version strings. Checks must be deterministic and not mutate repo content. All JSON files are ASCII, with stable keys to allow diff-based audit.

## Components (200-300 words)

`aaa-tools` is the primary runtime. Add a new CLI group `aaa pack` with subcommands `list`, `install`, and `show`. `list` fetches `registry_index.json`, prints ids and latest versions, and caches to `.aaa/registry_cache.json`. `install` resolves the registry URL, downloads the pack artifact, verifies checksum (if provided), extracts into `.aaa/packs/<id>/<version>/`, and updates `installed.json`. `show` lists installed packs and versions per repo. Update repo checks to discover pack checks from `.aaa/packs/*/*/checks/` and execute them in addition to built-in checks. Pack checks should be isolated and invoked through the existing eval runner API. The registry lives in a new repo (or a dedicated folder) with an index file and release artifacts; this is the only external dependency in v0.8. `aaa-tpl-docs` documents the protocol, pack structure, and installation path. The templates for sample packs will live as build inputs and not inside `aaa-tools`. CI should verify that a minimal pack install works in a clean repo and that `repo-checks` loads the installed checks. The plan avoids global config; every repo remains self-contained with `.aaa/packs/` and can pin versions. This also sets the stage for v0.9 private registries and v1.0 marketplace UX without touching the core installation logic.
