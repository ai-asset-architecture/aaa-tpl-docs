# AAA v0.9 Plan — Governance Compliance Dashboard (Snapshot)

## Plan Summary
v0.9 以「當日快照」為 MVP，將 nightly-governance 的原始數據聚合為可稽核（Markdown）與可視化（GitHub Pages）的雙輸出。流程分三段：Scan 產出 `nightly_governance.json`；Render 產出 `reports/audits/YYYY-MM-DD-governance.md` 與 `docs/dashboard/index.html`；Publish 由 docs repo 提交與 Pages 部署。合規率採 repo-based：任何 check 為 `fail` 或 `error` 即視為不合規；`archived=true` 不納入分母並顯示 N/A。此階段不做趨勢、外部 BI 與即時事件流，確保 v0.9 可快速落地並形成穩定治理證據鏈。

## Data Schema (Snapshot)
主輸出為 `nightly_governance.json`，結構：
- `generated_at`, `org`, `repo_count`, `compliance_rate`
- `repos[]`: `name`, `archived`, `repo_type`, `compliant`, `checks[]`
- `checks[]`: `id`, `status`（Enum: `pass|fail|error|skip`）

計算規則：
- `compliant = all(checks.status == "pass")`
- `fail` 或 `error` 視為不合規
- `archived=true` 時 `compliant=null`，不納入分母，但需列在清單中

Markdown 報告以表格呈現：`Repo | Type | Compliance | Failing Checks | Last Scan`。
HTML 儀表板顯示 KPI（合規率大字）、Failing list、完整清單。

## Components & Flow
- **Producer**: `nightly-governance` workflow（aaa-actions）生成 JSON。
- **Renderer**: `aaa-tools` 提供 `render-dashboard`（建議置於 `aaa/ops/render_dashboard.py`），讀取 JSON 產出 MD + HTML；模板放在 `aaa-tools/templates/`。
- **Publisher**: `aaa-tpl-docs` 定時觸發（schedule），提交報告與部署 Pages。
- **Alerting**: 閾值阻斷（`compliance_rate < 0.8`）使 workflow 失敗；使用 GitHub 既有通知即可。

## Out of Scope (v0.9)
- 趨勢與歷史聚合（留待 v0.10+）
- 外部 BI / 即時事件流
- 跨組織匯總
