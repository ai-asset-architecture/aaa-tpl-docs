# v1.0 Architecture Definition — Enterprise Delivery

## Goal
將 AAA 治理從「建議性」提升為「強制性」：以 Org‑level Rulesets 強制合規 Gate，並提供可稽核的證據鏈與長期快照。

## Scope
- **In Scope**
  - Repository Rulesets（Org 層級）強制 `governance-gate`
  - `aaa-gate` workflow 作為唯一合規入口（固定 job name）
  - Gate Evidence（PR 檢查結果 + JSON/MD 報告）
  - Nightly Audit 保留，作為歷史快照與審計依據
- **Out of Scope**
  - 私有 Registry 認證
  - 付費/計費/工單系統

## Architecture Overview
v1.0 將 **Ruleset** 作為合規強制層，並以 **aaa‑gate** workflow 作為唯一 Gate。Ruleset 綁定固定 job 名稱（`governance-gate`），避免 matrix 產生動態名稱造成 PR 死鎖或空洞化。Nightly Audit 仍負責「全量快照」，但不取代 Gate。

## Governance Enforcement (Rulesets)
- 規則集包含：
  - Require status checks to pass → `governance-gate`
  - Require pull request
  - Require review + CODEOWNERS
- `aaa-gh-org-audit` 需驗證：
  - Ruleset 是否仍綁定 `governance-gate`
  - Repo 是否實際產生對應 check‑runs（避免名稱漂移）

## Gate Workflow (aaa-gate)
- workflow 設定：
  - job name **必須固定**：`governance-gate`
  - 禁止 matrix 導致 job name 變動
- Gate 任務：
  1) `verify-ci`（required checks 存在性）
  2) `repo-checks`（repo_type / orphaned_assets / checks manifest）
  3) `agent_safety`（expected block = pass）
  4) Evidence outputs（JSON/MD）

## Evidence Chain
- PR Gate evidence：`checks + report.md + nightly_governance.json`
- Nightly audit evidence：`reports/audits/*` 與 `docs/dashboard/*`

## Success Metrics
- 所有 PR 必須通過 `governance-gate` 才可 merge
- Nightly audit 具備完整稽核紀錄與趨勢
- Job 名稱穩定、Ruleset 綁定一致

## Risks & Mitigations
- **Job name drift**：workflow 明確 `name: governance-gate` + audit 驗證
- **Ruleset 綁定漂移**：org audit 每晚檢查
- **矩陣導致 gate 名稱不一致**：禁止 matrix job name
