# v1.1 Architecture Definition — Semantic Era

## Goal
開啟 AAA 的「語義時代」：讓治理系統具備與 AI Agent 直接對話的能力，透過語義化輸出引導 Agent 進行自動化修復與決策。

## Scope
- **In Scope**
  - **AI-First CLI Protocol**：`aaa check/run/audit` 支援 `--format=llm` 與 `--format=json`。
  - **Semantic Error Mapping**：錯誤訊息包含策略引用與具體修復建議（Fix Suggestions）。
  - **Rich Diagnostics**：故障診斷包含底層 Runner 的詳細失敗軌跡（Details）。
  - **MCP Server Bridge**：實驗性 FastMCP 整合，將 AAA 能力暴露為 Agent Tools。
- **Out of Scope**
  - 分散式語義緩存
  - 完整 Agent 自治閉環 (v2.0 預定)

## Architecture Overview
v1.1 引入了 **Output Formatter** 層，將核心治理邏輯產出的原始數據轉化為多樣化的語義表示。這使得 AAA 從單純的 Linter 演進為 Agent 的 **Perception Layer**（感知層）。

## Semantic Protocol
- **Tag-based LLM Output**：使用 `<RULE_ID>` 與 `<EXEC_SUGGESTION>` 標籤，方便 Agent 快速 Regex 提取指令。
- **Deep JSON Metadata**：不再只回傳錯誤代碼，改為回傳包含具體違法位置與數據的深層 JSON。

## MCP Integration
- 作為 AAA 進駐 AI IDE（如 Cursor）的橋樑。
- 提供 `aaa_check` 與 `aaa_audit` 作為標準 MCP Tools。

## Success Metrics
- Agent 對 `aaa check` 失敗的理解率提升至 100%。
- 減少開發者手動查閱文檔的時間，修復建議準確率 ≥ 90%。

## Risks & Mitigations
- **Context Window Overload**：LLM 格式若過長會浪費 Token。→ **Mitigation**: 採用摘要標籤設計，僅保留關鍵 Context。
- **Hallucination in Fix suggestions**：提供錯誤的建議。→ **Mitigation**: 建議內容與 `ERROR_MAP` 綁定，由人類架構師維護。
