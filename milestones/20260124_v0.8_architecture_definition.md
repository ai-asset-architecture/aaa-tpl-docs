# Milestone: v0.8 Architecture Definition (20260124)

## Goal
將 AAA 從「單體治理框架」轉型為「可插拔的資產市集」，讓 Evals/Prompts/Templates 以 Pack 形式被發布、安裝與更新。

## Key Deliverables

1) Pack Architecture
- `pack.manifest.json` schema：定義 pack 內容、版本、相依性與用途（evals/prompts/templates）。
- `aaa pack` CLI：新增 `build / publish / install / list` 指令（只做最小可行功能）。

2) The Registry
- `ai-asset-architecture-registry`（新 repo）：作為官方 pack index（metadata + download refs）。
- 支援 `aaa pack install <pack>@<version>` 從 registry 解析與安裝。

3) Initial Packs (MVP)
- `pack-governance-core`：v0.7 的基礎治理能力（orphaned_assets / repo_type rules）。
- `pack-agent-safety`：v0.6/0.7 的安全檢查（含 deferred 的 DLP/secret scan）。
- `pack-starter-saas`：示範用模板包（示範 UI/Service 模板結構）。

## Success Metrics
- 新 repo 能以 `aaa pack install agent-safety@v1.0` 注入能力。
- `aaa-tools` 核心不再夾帶模板內容，改由 pack 供應。
- registry 解析與安裝在 CI 中可重現（deterministic）。

## Scope Boundaries
- In Scope：公開 GitHub repo 作為 registry、基礎 pack 安裝與版本解析。
- Out of Scope：私有 registry 認證、計費與支付流程（v0.9+ / v1.0+）。

## Notes
- v0.7 deferred 的 DLP / Secret Scan 以 pack 形式交付，避免拖累核心 CLI。
- Marketplace 定位為「資產分發」，不涉及商業交易。

## Technical Alignment (Before Plan)

1) Pack Installation Path (物理型態與安裝路徑)\n
- v0.8 採 Repo Local：`repo_root/.aaa/packs/`。\n
- 原因：每個 Repo 可依賴不同版本，不汙染全域環境。\n

2) Registry Protocol (註冊中心協議)\n
- Registry repo 根目錄提供 `registry_index.json`。\n
- CLI 以此 JSON 進行 `aaa pack list` 與版本解析。\n
- 格式示意：\n
```json
{
  "packs": {
    "agent-safety": {
      "latest": "1.0.0",
      "versions": {
        "1.0.0": "https://github.com/.../releases/download/v1.0.0/pack.zip"
      }
    }
  }
}
```

3) Pack Content Boundary (內容邊界)\n
- Pack 為標準結構的 ZIP/Tarball。\n
- 範例：\n
```
pack-agent-safety/
├── pack.manifest.json
├── checks/
├── templates/
└── rules/
```

4) Repo Checks Integration\n
- `repo-checks` 支援從 `.aaa/packs/*/checks/` 動態載入檢查腳本。\n
