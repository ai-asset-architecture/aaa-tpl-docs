# Cross-Version Review Note: v2.1.1 through v2.1.4 Old System vs New System

- date: 2026-04-04
- versions: v2.1.1, v2.1.2, v2.1.3, v2.1.4
- artifact_type: approval-context review note
- normative_status: interpretive_only_not_normative

## Summary
`v2.1.1` 到 `v2.1.4` 若依目前 Step1 邏輯與後續 Step2/Step3 完整做完，拿到的不是一個新 CLI，也不是一個可直接跑的 session engine，而是一組 AAA governance runtime 的母法底座。

這組底座的價值不在於立刻新增多少 operator-facing 功能，而在於後續做 CLI、agent runtime、repo checks、ops workflow 時，不必再重新發明治理語義，並且能以 contract 為準建立可驗證、可審計、可防漂移的執行層。

## What These Four Versions Actually Deliver
### v2.1.1
將 `tool contract` executable adoption 與 `command registry` machine-parseable binding 鎖成可機械解析 bundle，使 command 不再靠 prose 描述綁 tool。

### v2.1.2
將 multi-repo/worktree identity guard 鎖成 contract，明確 canonical repo root、worktree instance、validator rules、runtime guard 與 target applicability。

### v2.1.3
將 current truth source、supporting source、preflight checks 與 contamination blocking 鎖成 preflight bundle，防止 local operation logs 非法升格為 current truth。

### v2.1.4
將 session-facing readiness state 與 orchestration-related state shape 鎖成 machine-checkable contract，讓 readiness 不再依賴操作者主觀判斷。

## Governance Runtime Foundation
四版合起來形成 AAA 的：

- `Capability law`
- `Target law`
- `Truth law`
- `Readiness law`

也就是 `Capability × Target × Truth × Readiness` 的治理底座。這是後續 Step2/Step3 能否做成 fail-closed、可驗證、可審計系統的前置條件。

## Old System vs New System
### Old System
- command/tool 關係依賴操作者理解與文件 prose
- workspace root / repo root / worktree instance 容易被混用
- current truth 容易被 local logs、terminal output、scratch notes 汙染
- readiness 主要靠感覺與操作經驗判斷
- runtime convenience 常常先於治理母法

### New System
- command/tool 有 machine-parseable binding
- target legality 與 applicability 先被契約化
- canonical current truth 與 supporting evidence 明確分層
- readiness 轉成 state contract 與 checks
- canonical law 先於 adapter，adapter 先於 runtime

## Immediate Benefits
- reviewer 可以直接對照 canonical contracts 與 baseline artifacts，不必再靠口頭共識補語義
- Step2 CLI/runtime/validator adoption 不再從零決定語義
- `aaa-tools` 的 implementation mirror 更難反向奪權
- 後續 agent 接手時，不必再從 local clues 猜測何者為 truth、target、readiness
- governance gate 可從 heuristic 逐步轉向 fail-closed

## What Is Still Missing
完成這四版後，仍未直接得到：

- 完整可跑的 AAA CLI
- 完整 session engine
- operator console / readiness panel
- command dispatcher
- full runtime preflight implementation
- 全量 repo checks / ops workflows 的執行接線

這些都屬於 Step2 以後的執行層。

## Step2 Implications
後續 Step2 應依這四版的 contract 分別承接：

- `v2.1.1`：tool/command adoption 與 validator/adapter 消費
- `v2.1.2`：identity validator 與 runtime guard
- `v2.1.3`：context/runtime preflight 與 contamination blocking
- `v2.1.4`：session-facing readiness resolver 與 operator-facing status surface
