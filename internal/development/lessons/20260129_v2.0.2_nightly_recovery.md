# Lesson Learned: v2.0.2 Nightly Governance Recovery

## Summary
**ZH-TW:** 本次事件顯示 Nightly 治理鏈路對 repo_type 錨點與 README 規範高度敏感。缺少 `.aaa/metadata.json` 會讓 repo_type_consistency 全面失敗；跨 repo push 會被權限阻斷；未落地 JSONL 會導致無法追根因。
**EN:** This incident shows Nightly governance is highly sensitive to repo_type anchors and README compliance. Missing `.aaa/metadata.json` cascades into repo_type_consistency failures; cross-repo push is blocked by permissions; and without JSONL persistence, root-cause analysis becomes impossible.

## Key Lessons
1. **Repo-Type Anchor is Mandatory**
   - `.aaa/metadata.json` must be version-controlled across repos. Without it, repo_type consistency checks fail everywhere.
2. **Cross-Repo Push is Fragile**
   - Nightly should not push into `aaa-docs`. Use a self-managed workflow in `aaa-docs` to sync dashboard artifacts.
3. **Evidence First, Failure Second**
   - Persist repo-checks JSONL before failing the job to enable post-mortem analysis.
4. **Workflow Contract Must be Explicit**
   - `render-dashboard` requires `--md-out`. If missing, workflow fails even when data exists.
5. **Reusable Workflow Dependencies Must Be Explicit**
   - `checks.manifest.json` must be available by checking out `aaa-actions` inside the gate workflow.

## What Changed
- Introduced repo_type anchors across repos.
- Shifted dashboard publishing to `aaa-docs` workflow.
- Persisted repo-checks JSONL artifacts.
- Hardened gate workflow dependencies.

## Follow-ups
- Add an auto-check that refuses PRs if `.aaa/metadata.json` is missing.
- Add a standard runbook for Nightly recovery (see runbook asset).
