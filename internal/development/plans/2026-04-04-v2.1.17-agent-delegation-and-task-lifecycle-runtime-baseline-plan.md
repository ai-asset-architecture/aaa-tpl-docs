## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 task lifecycle 與 delegation boundary，不允許 prose-only fallback。
2. schema 必須明確定義 task states、ownership scope、handoff evidence 與 verification requirement。
3. 本版只管 execution lifecycle，不定義 extension loading。
4. 不得做無邊界 agent spawning 或自治 agent platform。
5. fail example 必須表達至少一個未經 verification 即 handoff 完成，或超出 ownership scope 的 delegation 違規情形。
6. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
7. `version_index.md` 已追加 `v2.1.17` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`，且 `v2.1.11 ~ v2.1.19` Step1 row wording 必須一致。

## Out of Scope (Step1)
- 本版只建立 Step1 runtime-plane baseline，不實作 runtime entry / validator / CLI wiring / frontend publish / workflow artifact。
- 不定義 plugin / skill loading plane。
- 不修改 `aaa-tools`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 task lifecycle 與 ownership 未先固定，delegation runtime 很容易演變成不可審計併發執行。
- 若 verification requirement 不先契約化，delegated result 會失去 closeout 可追溯性。

## Triple-Summary Protocol (v2.1.17)
### 1. Strategic Plan (戰略計畫摘要)
讓 AAA 有任務生命週期，而不是只有 command 被執行過的痕跡。

### 2. Schema Evolution (結構演進摘要)
新增 `agent-delegation-and-task-lifecycle-runtime.v0.1.schema.json`，固定 task states、ownership、handoff 與 verification boundary。

### 3. Component Architecture (組件架構摘要)
Step1 僅交付 task lifecycle bundle 與 pass/fail fixtures；Step2 若啟動，才把此 bundle 對應到 `aaa-tools` delegation runtime。
