## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 extension plane，不允許 prose-only fallback。
2. schema 必須明確定義 manifest、load mode、register boundary、trust boundary 與 injection target。
3. 本版只管 load / register / trust boundary，不定義 task lifecycle。
4. 不允許 extension 反向奪取 canonical law。
5. fail example 必須表達至少一個未經 trust boundary 即注入 runtime，或 extension 反向覆寫 canonical semantics 的違規情形。
6. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
7. `version_index.md` 已追加 `v2.1.18` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`，且 `v2.1.11 ~ v2.1.19` Step1 row wording 必須一致。

## Out of Scope (Step1)
- 本版只建立 Step1 runtime-plane baseline，不實作 runtime entry / validator / CLI wiring / frontend publish / workflow artifact。
- 不建立大型 marketplace 生態。
- 不修改 `aaa-tools`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 extension plane 不先定義 trust boundary，未來注入點會直接污染 core runtime。
- 若本版和 `v2.1.17` 邊界不清，execution lifecycle 與 extension loading 會相互咬住。
