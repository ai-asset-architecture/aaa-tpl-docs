## Acceptance Criteria
1. public readiness verdict family 必須固定為 `support_ready`、`orchestration_ready`、`execution_ready`、`ready_with_gap`、`not_ready`。
2. `invalid` 必須被固定在 adjudication validity gate，不得出現在 readiness verdict family。
3. blocker vs gap distinction、verdict precedence、evidence requirement 必須 machine-readable。
4. 本版不得在 Step1 階段宣稱任何 topology 已取得 execution readiness。
5. `version_index.md` 與 `workflow_index.md` 已新增 `v2.1.45` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`。

## Step2 Scarcity Rationale
- 不能 bridge-only 的原因：readiness certification 若無 executable evidence，無法證明 adjudication law 與 evidence requirement 真正被 runtime 執行。
- 不能被既有 execution package 吸收的原因：既有 workflows 沒有 readiness verdict engine 與 validity gate separation。
- 預設 execution carrier：`aaa-tools/.github/workflows/v2-1-45-readiness-certification-baseline.yml` 草案，待 reviewer 批准後才可升格為 Step2 carrier。

## Out of Scope (Step1)

- 不用 `invalid` 取代 readiness verdict。
- 不在第一條 canonical path 未 productize 前擴張第二條 public path。
