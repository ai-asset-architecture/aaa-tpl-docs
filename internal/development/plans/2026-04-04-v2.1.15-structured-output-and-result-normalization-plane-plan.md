## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 normalized result envelope，不允許 prose-only fallback。
2. schema 必須明確區分 machine-safe、human-safe、operator-safe output classes。
3. schema 必須固定至少 `status`、`errors`、`warnings`、`artifact_refs`、`normalized_payload` 這類共同輸出欄位。
4. schema 必須明確表達 `normalized_payload` 與 `artifact_refs` 的角色分工與 precedence，不得允許 path-specific artifact 反向奪取 normalized result source 地位。
5. prose-only result 不得構成 shared runtime result source。
6. fail example 必須表達至少一個 path-specific output 或 artifact precedence 未經 normalization / precedence control 就被當成正式 shared result 的違規情形。
7. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
8. `version_index.md` 已追加 `v2.1.15` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`，且 `v2.1.11 ~ v2.1.19` Step1 row wording 必須一致。
9. `version_index.md` 的 `status` / `run_ref` / step wording 必須使用 canonical phrase，不得出現同義改寫。

## Out of Scope (Step1)
- 本版只建立 Step1 runtime-plane baseline，不實作 runtime entry / validator / CLI wiring / frontend publish / workflow artifact。
- 不建立大型 reporting product。
- 不修改 `aaa-tools`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 output normalization 不先固定，shared dispatch 與 workflow runtime 仍會被 heterogeneous output 污染。
- 若 prose-only result 仍可奪權，evidence 與 operator surface 將難以穩定消費結果。
