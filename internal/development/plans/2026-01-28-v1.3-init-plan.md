## Triple-Summary Protocol (v1.3)

### 1. Strategic Plan (戰略計畫摘要)
AAA v1.3 的戰略雙箭頭為「降低治理門檻」與「鞏固工程地基」。

**Critical Action: Baseline Lockdown (基準線鎖定)**
已執行全量 Coverage Report，結果為 **48%**。
**Rule (Stop the Line)**: 核心組件覆蓋率未達 **80%**，CI 將自動阻擋 `aaa/compiler/` 目錄的任何 Feature Merge。這將強制團隊優先償還技術債務。

### 1.1 Strategic Amendment: The Diamond Standard (鑽石分級防禦)
*Ref: User Insight 2026-01-28*
AAA 作為上游模具 (Upstream Source)，80% 覆蓋率不足以防止供應鏈污染。我們採用分層標準：

#### 🔴 **Zone Zero: The DNA (核心基因) - Target 100%**
- **Scope**: Code generators, Templates, Scaffolding Logic.
- **Components**: `aaa/compiler/generator.py`, `aaa/init_commands.py` (scaffold parts), `templates/`.
- **Requirement**: 100% Coverage + Idempotency/Snapshot Tests.

#### 🟡 **Zone One: The Enforcer (執法者) - Target 95%**
- **Scope**: Checkers, Validators, Parsers.
- **Components**: `aaa/compiler/parser.py`, `aaa/compiler/schema.py`.
- **Requirement**: 95% Coverage.

#### 🟢 **Zone Two: The Interface (介面層) - Target 80%**
- **Scope**: CLI glue, Logging.
- **Requirement**: 80% Coverage.

一方面，透過 **Governance Compiler**，我們將治理規則的定義權下放給非技術管理者... (後續同前)

### 2. Schema Evolution (結構演進摘要)
為支援 Policy Compiler，我們將引入 **Policy DSL (Domain Specific Language)** 的初版 Schema。這將是一個基於 YAML/JSON 的中間表達層 (Intermediate Representation)，用於描述「規則意圖」、「檢查邏輯」與「修復建議」。同時，為了符合 **Schema Hardening** 原則，所有新舊 Schema 都將逐步遷移至嚴格的 Pydantic 模型，移除所有 `Any` 或模糊型別定義，確保 Agent 能精確理解數據結構。

### 3. Component Architecture (組件架構摘要)
架構上，`aaa-tools` 將新增 `compiler` 子系統，包含 `Parser` (解析自然語言) 與 `Generator` (生成 Python Check Code)。這將是一個「編譯器架構」，未來可抽換前端 (LLM vs Rule-based) 或後端 (Python vs Rego)。同時，既有的 `aaa-tools/tests` 目錄將進行重構，建立標準化的測試腳手架 (Test Scaffold)，以加速 v0.x 組件的測試補完工作。
