# v1.2 Implementation Plan - Semantic Registry (Refined)

> 本文件遵循 AI Constitution 2.2 之 Triple-Summary Protocol。
> **Updates (2026-01-28 20:55)**: 納入 Architect 指導的 Version Handshake 與 Object-Centric 策略。

## 1. Triple-Summary (v1.2)

### A. Strategic Plan (戰略計畫摘要)
AAA v1.2 的核心戰略在於實現「語義化治理」。隨著 AAA 組織規模的擴張，單純的列表式 Registry 已無法滿足 AI Agent 對於資產能力的動態探索需求。本計畫將透過引入 **「自然語言描述 (Natural Language Descriptors)」** 與「能力查詢接口」，將 AAA 轉化為一個具備自我描述能力的「資產作業系統」。這不僅能顯著提升 Agent 在複雜多 Repo 環境下的資產定位效率 (RAG-Ready)，更為後續 v1.5 的自動修復與 v2.0 的 Agent OS 奠定堅實的架構基礎。戰略重點首要在於定義與標準化 `Capability API`，確保與 MCP (Model Context Protocol) 的深度相容性。

### B. Schema Evolution (結構演進摘要)
在結構層面，v1.2 將迎來 `registry_index.json` 的二次重大升級（v2 Schema）。核心變動包括：
1. **Object-Centric Governance**：從扁平列表轉向以 `object_type` 為核心的繼承模型。初期鎖定四大核心類型：`service` (API治理), `library` (版號治理), `data-pipeline` (Schema治理), `infra-as-code` (安全治理)。
2. **Semantic Capabilities**：`capabilities` 欄位將採用自然語言描述（如 "enforces PEP8 compliance"）以利於向量檢索。
3. **Version Handshake**：引入 `schema_version` 與 `min_cli_version` 欄位，實施「Fail Fast」策略，確保 CLI 版本兼容性。

### C. Component Architecture (組件架構摘要)
技術組件上，`aaa-tools` 將新增 `registry.query` 子模組，用於解析語義查詢並執行能力匹配邏輯。`ai-asset-architecture-registry` 需更新 CI 流程驗證語義完整性。**遷移策略**上，初期將採用 Dual-Publish 模式（同時發布 `registry_v1.json` 與 `registry_v2.json`），給予舊專案 2-4 週緩衝期。`aaa-tpl-docs` 將新增 v2 Schema 的規格文檔與 `Capability Catalog` 生成腳本。
