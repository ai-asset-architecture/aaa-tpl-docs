# v1.2 Implementation Plan - Semantic Registry (Initialization)

> 本文件遵循 AI Constitution 2.2 之 Triple-Summary Protocol。

## 1. Triple-Summary (v1.2)

### A. Strategic Plan (戰略計畫摘要)
AAA v1.2 的核心戰略在於實現「語義化治理」。隨著 AAA 組織規模的擴張，單純的列表式 Registry 已無法滿足 AI Agent 對於資產能力的動態探索需求。本計畫將透過引入「語義元數據」與「能力查詢接口」，將 AAA 轉化為一個具備自我描述能力的「資產作業系統」。這不僅能顯著提升 Agent 在複雜多 Repo 環境下的資產定位效率，更為後續 v1.5 的自動修復與 v2.0 的 Agent OS 奠定堅實的架構基礎。戰略重點首要在於定義與標準化 `Capability API`，確保與 MCP (Model Context Protocol) 的深度相容性。

### B. Schema Evolution (結構演進摘要)
在結構層面，v1.2 將迎來 `registry_index.json` 的二次重大升級（v2 Schema）。核心變動包括：1. 從扁平的 Pack 列表轉向以 `object_type` 為核心的繼承模型，允許不同專案類型（如 Service vs. App）自動掛載特定治理策略；2. 在 Pack Manifest 中引入高度語義化的 `capabilities` 欄位，利用向量友好的描述取代傳統關鍵字。此外，`index.json` 將擴展 `governance_inheritance` 節點，明確紀錄專案如何繼承組織級的憲法準則。

### C. Component Architecture (組件架構摘要)
技術組件上，`aaa-tools` 將新增 `registry.query` 子模組，用於解析語義查詢並執行能力匹配邏輯。`ai-asset-architecture-registry` 則需要更新其 CI 流程，以自動驗證新註冊 Pack 的語義完整性。`aaa-tpl-docs` 作為治理文檔的中樞，將新增 `Capability Catalog` 生成腳本，確保人類開發者也能直觀瀏覽 Registry 的語義化輸出。各組件間將透過標準化的 JSON-RPC 或 MCP 接口進行通訊，實現跨 Repo 的無縫解耦。
