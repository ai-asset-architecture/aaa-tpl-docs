## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 workflow / runbook runtime，不允許 prose-only fallback。
2. schema 必須固定 step graph、dependency、handoff artifact、step outcome 與 workflow-level readiness gate。
3. 本版只處理 AAA 內部 multi-step execution，不擴成通用 BPM 平台。
4. 不得新增獨立 workflow law island；僅 runtime-plane 化既有 core line。
5. fail example 必須表達至少一個 step dependency 被繞過或 handoff artifact 未受治理的違規情形。
6. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
7. `version_index.md` 已追加 `v2.1.16` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`，且 `v2.1.11 ~ v2.1.19` Step1 row wording 必須一致。

## Out of Scope (Step1)
- 本版只建立 Step1 runtime-plane baseline，不實作 runtime entry / validator / CLI wiring / frontend publish / workflow artifact。
- 不建立通用 BPM / business workflow 平台。
- 不修改 `aaa-tools`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 multi-step handoff 與 dependency law 不先固定，後續 runbook runtime 很容易退化成 ad hoc script chaining。
- 若 workflow-level gate 不明確，evidence 與 readiness 將只能逐步判讀，無法閉環。
