本版屬 `mandatory core absorption line`；可引用 shared canonical law，但不得重新定義、覆寫或吸收 `v2.1.1` 到 `v2.1.10` 的 primary scope；本版只定義 permission context、decision mode 與 execution gate。

## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 runtime permission gate，不允許 prose-only fallback。
2. schema 必須明確定義 permission context、decision mode、interactive boundary 與 non-interactive boundary。
3. 本版只 runtime-plane 化既有 authority model，不得新增新的 primary authority law。
4. gate 決策至少必須區分 `allow`、`deny`、`ask`、`auto_deny`。
5. fail example 必須表達至少一個未經授權仍嘗試執行，以及至少一個 non-interactive path 仍要求人工互動的違規情形。
6. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
7. `version_index.md` 已追加 `v2.1.11` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`，且 `v2.1.11 ~ v2.1.19` Step1 row wording 必須一致。
8. `version_index.md` 的 `status` / `run_ref` / step wording 必須使用 canonical phrase，不得出現同義改寫。

## Out of Scope (Step1)
- 本版只建立 Step1 runtime-plane baseline，不實作 runtime entry / validator / CLI wiring / frontend publish / workflow artifact。
- 不新增新的 authority class。
- 不修改 `aaa-tools`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 permission gate 退回 path-local heuristic，authority contract 將無法真正執行。
- 若 interactive / non-interactive boundary 未先固定，後續 workflow 與 delegation 會出現不可審計授權行為。

## Triple-Summary Protocol (v2.1.11)
### 1. Strategic Plan (戰略計畫摘要)
先把 authority/permission 從靜態 law 變成真正可判定、可記錄的 runtime gate，作為後續 core line 的執行入口防線。

### 2. Schema Evolution (結構演進摘要)
新增 `permission-and-authorization-runtime-gate.v0.1.schema.json`，固定 permission context、decision mode、interactive boundary 與 gate outcome。

### 3. Component Architecture (組件架構摘要)
Step1 僅交付 permission gate bundle 與 pass/fail fixtures；Step2 若啟動，才把此 bundle 對應到 `aaa-tools` permission runtime。
