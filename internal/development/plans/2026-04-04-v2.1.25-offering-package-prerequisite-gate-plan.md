## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 prerequisite gate，不允許 prose-only fallback。
2. gate verdict 至少必須區分 `pass`、`fail`、`pass_with_gap`。
3. schema 必須明確聲明 prerequisite verdict 只屬 pre-adoption gate output，不構成 package activation、readiness 或 completion。
4. 本版不得外溢到 materialization、status/evidence 或 package activation semantics。
5. fail example 必須表達至少一個 gate verdict 被錯誤視為 activation，以及至少一個 `pass_with_gap` 被誤當完成的違規情形。
6. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
7. `version_index.md` 已追加 `v2.1.25` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`。
8. `version_index.md` 的 `status` / `run_ref` / step wording 必須使用 canonical phrase，不得出現同義改寫。

## Out of Scope (Step1)
- 本版只建立 Step1 runtime-plane baseline，不實作 runtime entry / validator / CLI wiring / frontend publish / workflow artifact。
- 不建立 package status / package evidence / package activation。
- 不修改 `aaa-tools`、`aaa-docs`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 prerequisite verdict 與 activation/readiness/completion 邊界不先切開，後續 package status 很容易被 gate verdict 誤取代。
- 若 `pass_with_gap` 的語義不先固定，後續 materialization 與 closeout 會出現虛假完成宣稱。

## Triple-Summary Protocol (v2.1.25)
### 1. Strategic Plan (戰略計畫摘要)
把 remote client 承接前提收斂成 machine-checkable prerequisite gate，讓 package 導入有正式前置判斷，而不是靠 README 自評。

### 2. Schema Evolution (結構演進摘要)
新增 `offering-package-prerequisite-gate.v0.1.schema.json`，固定 gate scope、checked prerequisites 與 verdict 邊界。

### 3. Component Architecture (組件架構摘要)
Step1 僅交付 prerequisite gate bundle 與 pass/fail fixtures；Step2 若啟動，才把此 bundle 對應到 `aaa-tools` package prerequisite runtime。
