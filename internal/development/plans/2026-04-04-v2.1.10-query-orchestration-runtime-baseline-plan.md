# Step1 Plan: v2.1.10 Query Orchestration Runtime Baseline

- date: 2026-04-04
- version: v2.1.10
- owner: AI Agent
- scope: Step1 only (contracts/governance assets)
- status: FOR_REVIEW

## Objective
建立 `v2.1.10` 的 Step1 契約基線，將 shared dispatch、result/evidence gate 與 session context snapshot 收斂成最小可重放的 query orchestration runtime loop。
本版可引用 shared canonical law，但不得重新定義、覆寫或吸收 `v2.1.1` 到 `v2.1.9` 的 primary scope；本版只定義 orchestration loop 的最小可用 request/turn lifecycle、write-back boundary 與 gating semantics。

## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 query orchestration runtime，不允許 prose-only fallback。
2. schema 必須明確固定 request/turn lifecycle、dispatch chain、context consumption、result gate、evidence gate 與 readiness gating。
3. query orchestration runtime 不得繞過 result/evidence promotion gate，亦不得繞過 session context snapshot boundary；任何 write-back 必須服從 `v2.1.8` 與 `v2.1.9` 的既有 runtime-plane constraints。
4. schema 必須明確限制 orchestration loop 只消費既有 runtime plane，不得新增新的 primary law。
5. fail example 必須表達至少一個繞過 promotion gate 或 snapshot boundary 的違規情形。
6. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
7. 本版目的是 runtime-plane 收斂，不構成 broader command family expansion。
8. `version_index.md` 已追加 `v2.1.10` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`。

## Out of Scope (Step1)
- 不實作 orchestration runtime entry 或 turn executor。
- 不新增新的 runtime adoption consumer family。
- 不修改 `aaa-tools`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 orchestration loop 被允許繞過 `v2.1.8` 或 `v2.1.9`，前面兩版 runtime plane 會直接失去守門能力。
- 若 request/turn lifecycle 與 write-back boundary 不先固定，後續 orchestration 很容易退化成不可重放的 ad hoc flow。

## Triple-Summary Protocol (v2.1.10)
### 1. Strategic Plan (戰略計畫摘要)
把 shared dispatch、result/evidence gate 與 session snapshot 串成最小可重放的 orchestration loop，讓 AAA 真正開始形成 shared runtime 系統。

### 2. Schema Evolution (結構演進摘要)
新增 `query-orchestration-runtime-bundle.v0.1.schema.json`，固定 request/turn lifecycle、write-back boundary 與 fail-closed gating semantics。

### 3. Component Architecture (組件架構摘要)
Step1 僅交付 orchestration runtime bundle 與 pass/fail fixtures；Step2 若啟動，才把此 bundle 對應到 `aaa-tools` orchestration runtime entry。
