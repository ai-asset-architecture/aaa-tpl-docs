## Acceptance Criteria
1. intermediate artifacts 必須可 machine-readable 區分 `client_authored` 與 `command_emitted`。
2. JSON contract 必須明示哪些 bundle 已自動化、哪些仍未自動化。
3. JSON contract 必須明示 topology/profile 限制，不得暗示所有 topology 一律可自動生成。
4. help/runtime spec 不得把 bundle generation baseline 誤寫成 orchestration runtime。
5. `version_index.md` 與 `workflow_index.md` 已新增 `v2.1.42` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`。

## Step2 Scarcity Rationale
- 不能 bridge-only 的原因：本版若要成立，必須有 command-emitted bundle 的 executable evidence；純 wording 無法證明 generation responsibility 已回收。
- 不能被既有 execution package 吸收的原因：現有 workflow 只覆蓋 select/resolve/help/status truth，未覆蓋 bundle generation。
- 預設 execution carrier：`aaa-tools/.github/workflows/v2-1-42-intermediate-bundle-generation-baseline.yml` 草案，待 reviewer 批准後才可升格為 Step2 carrier。
