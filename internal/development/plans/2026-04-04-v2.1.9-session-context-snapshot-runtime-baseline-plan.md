## Objective
建立 `v2.1.9` 的 Step1 契約基線，將既有 context law 收斂為 session context snapshot runtime plane。
本版可引用 shared canonical law，但不得重新定義、覆寫或吸收 `v2.1.1` 到 `v2.1.8` 的 primary scope；本版只定義 `context -> snapshot / reload / replay` 的最小可用 runtime plane。

## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 session context snapshot plane，不允許 prose-only fallback。
2. schema 必須明確固定 static context、dynamic context、snapshot persistence、reload semantics 與 replay semantics。
3. session context snapshot 屬 runtime-plane artifact；除非經既有 canonical law 明確允許，snapshot 不得反向升格為 canonical truth source。
4. reload / replay semantics 不得隱性更新或覆蓋 canonical current truth；任何回寫都必須經既有 canonical law 顯式允許。
5. schema 必須明確排除 `local_operation_logs` 與 `generated_runtime_summaries` 冒充 snapshot canonical input。
6. fail example 必須表達至少一個 snapshot 試圖反向升格為 canonical truth 的違規情形。
7. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
8. `version_index.md` 已追加 `v2.1.9` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`，且四版 Step1 row wording 必須一致。

## Out of Scope (Step1)
- 本版只建立 Step1 runtime-plane baseline，不實作 runtime entry / validator / CLI wiring / frontend publish / workflow artifact。
- 不處理 result artifact promotion gate 的 primary scope。
- 不修改 `aaa-tools`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 snapshot 被允許反向升格為 canonical truth，context runtime plane 將直接越權。
- 若 reload/replay semantics 不先固定，後續 session runtime 很容易產生不可審計的 context reuse。

## Triple-Summary Protocol (v2.1.9)
### 1. Strategic Plan (戰略計畫摘要)
把 context 從前置驗證推進成 session runtime 的正式輸入面，為後續 orchestration loop 提供可重放的 snapshot plane。

### 2. Schema Evolution (結構演進摘要)
新增 `session-context-snapshot-runtime-bundle.v0.1.schema.json`，固定 snapshot assembly、persistence、reload 與 replay 邊界。

### 3. Component Architecture (組件架構摘要)
Step1 僅交付 session context snapshot bundle 與 pass/fail fixtures；Step2 若啟動，才把此 bundle 對應到 `aaa-tools` session snapshot runtime。
