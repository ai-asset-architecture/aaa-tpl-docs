# Implementation Plan: v2.0.4 Init Plan Presets (v2.0 Plan Upgrade)

## Goal Description
Upgrade the AAA init plan to v2.0 by introducing a single plan file that supports **Preset A (Lean)** and **Preset B (Governance-Native)** via `presets` + `default_preset`, ensuring `.github` is always included and aligning remote user adoption with AAA declaration benefits.

## User Review Required
> [!IMPORTANT]
> - **Schema Expansion**: `plan.schema.json` must be extended to support `presets` and `default_preset` (breaking change for strict validation).
> - **Preset Behavior**: Default preset must be **Governance-Native** and must include `.github`.
> - **Backwards Compatibility**: If `presets` is absent, tooling must still accept legacy `repos`.
>
> **Decision (2026-01-30)**:
> - **Do NOT enum-validate repo_type in schema** for v2.0.4.
> - Rationale: avoid breaking validators; align nightly by **metadata-first**, then expand repo coverage.
> - Optional hardening: allow any repo_type, but emit **WARN unknown_repo_type** (non-blocking).

## Proposed Changes
### [aaa-tools]
#### [NEW] runbooks/init/plan.v2.0.json
- Add `default_preset` and `presets` blocks (Lean + Governance-Native).
- Define repo lists with `.github` mandatory in both presets.

#### [MODIFY] specs/plan.schema.json
- Extend schema to allow `presets` and `default_preset`.
- Preserve legacy `repos` for backward compatibility.

#### [MODIFY] aaa/init_commands.py
- Resolve `repos` from `presets[default_preset]` when present.
- Add CLI `--preset` override to select preset explicitly.
- Fallback to legacy `repos` only when `presets` absent.

### [aaa-docs]
#### [MODIFY] bootstrap/ai_bootstrap.md
- Document v2.0 plan usage and preset selection guidance.

#### [NEW/MODIFY] bootstrap/cli_connection_guide.md
- Add `aaa init --plan ...` example for presets.

## Compatibility Matrix
| Plan format | aaa-tools version | Behavior | Failure mode | Fallback | User action |
| --- | --- | --- | --- | --- | --- |
| `presets` + `default_preset` | Preset-aware | Resolve by presets | preset_not_found / schema_invalid | None | Fix preset key or schema |
| legacy `repos` only | Legacy | Resolve legacy repos | none | N/A | Upgrade plan if presets needed |
| mixed (`presets` + `repos`) | Preset-aware | Presets take precedence | legacy repos ignored | None | Remove legacy repos or update docs |
| `presets` on old tool | Legacy-only | Validation fails | schema_error | Use legacy plan | Upgrade aaa-tools |

## Resolution Order
1. `--preset <name>` (explicit)
2. `default_preset`
3. legacy `repos` (only if `presets` absent)

## Error Policy
- `--preset` 指向不存在 preset → **FAIL FAST**（列出可用 preset keys）
- `default_preset` 指向不存在 preset → **FAIL FAST**（列出可用 preset keys）
- 嚴禁 silent fallback（除非進入 legacy mode，且必須提示 `MODE=legacy`）
- `presets` 存在但缺 `.github` → **FAIL FAST**（不得自動補）
- mixed (`presets` + legacy `repos`) → **允許但警告**：`WARN legacy_repos_ignored=true`

## Triple-Summary Protocol (v2.0.4)
### 1. Strategic Plan (戰略計畫摘要)
透過「單檔 presets + default_preset」將初始化流程從模板生成升級為**治理宣言落地**。以 Governance-Native 作預設，確保遠端用戶落地即具備 Law/Proof/Execution/Context 分立；Lean 作為低摩擦入口，不犧牲最小治理承諾。此計畫將 AAA adoption 從「模板工具」提升為「治理繼承」。

### 2. Schema Evolution (結構演進摘要)
將 init plan 從單一 `repos` 擴展為 `presets`（多組 repo 清單）與 `default_preset`（預設選擇）。同時保留 `repos` 作為 legacy fallback，避免舊版 plan 失效。此變更屬於 schema 擴充，需同步調整 plan 驗證器與相關文檔。

### 3. Component Architecture (組件架構摘要)
核心變更在 `plan.schema.json` 與 `aaa/init_commands.py`：解析流程優先讀取 `presets[default_preset].repos`，若不存在則回退 legacy `repos`。計畫檔新增 `plan.v2.0.json` 作為 v2.0 預設入口；文件層則在 `ai_bootstrap.md` 與 CLI guide 中提供 presets 使用範例與選擇策略。
