## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 session persistence 與 transcript compaction，不允許 prose-only fallback。
2. schema 必須明確區分 session store、transcript classes、compacted transcript 與 replay input classes。
3. transcript 不得作 canonical truth source。
4. schema 必須以 machine-checkable enum / flag 固定 compacted transcript 與 canonical replay input 的關係，例如 `replay_input_eligibility=allowed|disallowed|allowed_with_boundary`，且不得破壞 audit reproducibility。
5. fail example 必須表達至少一個 compacted transcript 被錯誤當成 canonical truth 或未經邊界控制就作為 replay input 的違規情形。
6. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
7. `version_index.md` 已追加 `v2.1.13` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`，且 `v2.1.11 ~ v2.1.19` Step1 row wording 必須一致。
8. `version_index.md` 的 `status` / `run_ref` / step wording 必須使用 canonical phrase，不得出現同義改寫。

## Out of Scope (Step1)
- 本版只建立 Step1 runtime-plane baseline，不實作 runtime entry / validator / CLI wiring / frontend publish / workflow artifact。
- 不建立 full chat product surface。
- 不修改 `aaa-tools`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 transcript boundary 未固定，session runtime 可能錯把 transcript 當 current truth。
- 若 compaction 破壞 replay 或審計可重現性，後續 orchestration 將無法可信 closeout。

### 1. Strategic Plan (戰略計畫摘要)
補上 session persistence 與 transcript compaction 的治理邊界，讓 AAA 不只會跑 turn，也能可信地保存、壓縮、重放。

### 2. Schema Evolution (結構演進摘要)
新增 `session-persistence-and-transcript-compaction.v0.1.schema.json`，固定 session store、transcript class、compaction boundary 與 replay input law。

### 3. Component Architecture (組件架構摘要)
Step1 僅交付 session persistence bundle 與 pass/fail fixtures；Step2 若啟動，才把此 bundle 對應到 `aaa-tools` session store runtime。
