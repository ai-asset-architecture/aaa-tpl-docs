# Implementation Plan: v1.6 Multi-Agent Orchestration

## Goal Description
Implement "Traffic Cop" mechanisms to manage multi-agent collaboration in a shared workspace.
Core features:
1. **Agent Conflict Resolution**: Detect semantic conflicts when multiple agents touch the same files.
2. **File Locking**: Prevent race conditions.
3. **Workspace Isolation** (Basic): Ensure clean state before agent execution.

## User Review Required
> [!IMPORTANT]
> This feature introduces file locking (`.lock` files). If an agent crashes, locks might need manual clearing (`aaa lock clear`).

## Proposed Changes
### [aaa-tools]
#### [NEW] aaa/engine/locking.py

- `detect_conflict(path)`: Check git status/lock status.

#### [NEW] aaa/cmd/lock_commands.py

- `aaa lock release <path>`

#### [MODIFY] aaa/cli.py

## Triple-Summary Protocol (v1.6)
### 1. Strategic Plan (戰略計畫摘要)
Transform AAA from a "Passive Tool" to an "Active Traffic Controller".
Prevent the "Too Many Cooks" problem as agent density increases.

### 2. Schema Evolution (結構演進摘要)
- **Lock Schema** (`.aaa/locks.json`):
    ```json
    {
      "locks": {
        "README.md": {
          "owner": "agent-session-id",
          "acquired_at": "ISO8601",
          "expires_at": "ISO8601" // TTL (Default: 5 min)
        }
      }
    }
    ```
- **Logic**: `check_lock()` cleans up stale locks (where `now > expires_at`).

### 3. Component Architecture (組件架構摘要)
- `LockManager` (Zone Zero): Pure logic, handles JSON I/O and TTL enforcement.
- `LockCommand` (Zone Two): CLI interface.
- **Granularity**: File-Level Locking only (v1.7+ may consider Block-Level).
