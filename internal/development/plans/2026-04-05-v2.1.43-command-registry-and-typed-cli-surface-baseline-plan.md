## Current Truth Summary
目前 AAA CLI 雖已有 public command families，但 command metadata、availability law、help contract、artifact I/O 還沒有集中化 registry substrate；這會限制後續 orchestration/runtime 疊代。

## Objective
建立 `v2.1.43` 的 Step1 契約基線，在保留 Python/Typer 的前提下，正式引入 registry-driven、typed-help、availability-aware、lazy-dispatch-capable 的 CLI substrate。

## Upstream Runtime Laws Consumed
- `v2.1.37`
- `v2.1.38`
- `v2.1.41`
- `v2.1.42`

## Claude Code CLI Leverage Boundary
- 吸收：command registry metadata model、typed option/help surface、availability-aware command filtering、lazy-loaded subcommand architecture。
- 不吸收：Ink/React command return model、daemon/remote shell、heavy interactive shell。
- 固定策略：保留 Python/Typer，不做 CLI framework rewrite。

## No Semantics Override
- 本版只升級 CLI substrate，不重寫 AAA CLI framework。
- 本版不是 orchestration runtime。
- 本版不是 readiness certification。
- 本版不把 CLI registry 誤寫成 agent runtime shell。

## Acceptance Criteria
1. command descriptor 必須 machine-readable 集中化 `name/description/aliases/availability/is_enabled/is_hidden/output_modes/truth_boundary/automation_level`。
2. help contract 必須超出參數列表，能表示 artifact inputs/outputs 與 truth boundary。
3. availability law 必須被固定，且不得把不可用命令偽裝成一般 public surface。
4. lazy-dispatch capability 必須只被定義為 substrate 能力，不得被誤寫為 full runtime orchestration。
5. `version_index.md` 與 `workflow_index.md` 已新增 `v2.1.43` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`。

## Step2 Scarcity Rationale
- 不能 bridge-only 的原因：registry substrate 若不做 executable evidence，無法證明 help/availability/registry law 有真正被 runtime 消費。
- 不能被既有 execution package 吸收的原因：現有 workflows 沒有驗證 command registry、lazy dispatch、availability gating。
- 預設 execution carrier：`aaa-tools/.github/workflows/v2-1-43-command-registry-and-typed-cli-surface-baseline.yml` 草案，待 reviewer 批准後才可升格為 Step2 carrier。

## Out of Scope (Step1)
- 不改用 Node CLI。
- 不新增 interactive shell UI。
- 不把 Claude Code CLI 的 UI/runtime 模型直接移植到 AAA。

## Triple-Summary Protocol (v2.1.43)
### 1. Strategic Plan
把 AAA CLI 從「指令集合」提升為「可治理的 command system」。

### 2. Schema Evolution
新增 `command-registry-and-typed-cli-surface-baseline.v0.1.schema.json`，固定 registry metadata、help contract、availability law。

### 3. Component Architecture
Step1 只 formalize registry substrate；Step2 若啟動，才以 remote workflow 驗證 registry-driven CLI surface。
