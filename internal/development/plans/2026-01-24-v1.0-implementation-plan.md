# v1.0 Implementation Plan — Enterprise Delivery

## Objective
將合規從「建議」提升為「強制」，以 Org‑level Rulesets 綁定固定 job name（`governance-gate`）作為唯一 Gate，並維持 Nightly 作為稽核快照與趨勢證據鏈。

## Scope
- **In Scope**
  - Ruleset 設定與驗證（Org 層級）
  - `aaa-gate` workflow 設計與落地
  - Gate evidence 規格與輸出
  - Nightly audit 與 Gate 的一致性檢查
- **Out of Scope**
  - 私有 Registry 認證與計費
  - 付費 SLA / 工單流程

## Phase 1 — Ruleset 基線與 SSOT
1. 定義 `governance-gate` job name 規格（固定名稱，禁止 matrix 動態名稱）。
2. 建立 Ruleset 設定文件與套用策略（Org 層級）。
3. 在 `aaa-gh-org-audit` 增加規則：
   - Ruleset 是否綁定 `governance-gate`
   - Repo 是否產生對應 check‑runs

**Deliverables**
- Ruleset 規範文件
- Audit 規則更新

## Phase 2 — aaa-gate Workflow
1. 新增 `aaa-gate` reusable workflow（`aaa-actions`）。
2. Workflow steps：
   - `verify-ci`（required checks 存在性）
   - `repo-checks`（governance suite）
   - `agent_safety`（expected block = pass）
3. 固定 job 名稱 `governance-gate`。
4. Gate evidence：輸出 JSON + MD（PR evidence）。

**Deliverables**
- `aaa-actions/.github/workflows/aaa-gate.yaml`
- Evidence 輸出規格

## Phase 3 — 消費端導入與驗收
1. 將 Ruleset 套用到目標 repos（先試點）。
2. 驗證 PR 無法繞過 Gate。
3. 驗證 Nightly audit 仍能產生完整快照。
4. 補完 `aaa-tpl-docs` SOP 與 Gate 規範引用。

**Deliverables**
- 試點驗收報告
- SOP 更新

## Phase 4 — 監控與回滾機制
1. 增加 Gate 失敗時的行為說明與回復步驟。
2. 設置最小回滾（解除 Ruleset 或暫停 Gate）。

**Deliverables**
- 失敗處理與回滾流程

## Acceptance Criteria
- 所有 PR 必須通過 `governance-gate` 才可 merge。
- Gate job name 穩定，Ruleset 綁定一致。
- Nightly audit 仍保留完整證據鏈與趨勢。

## Risks & Mitigation
- **Job 名稱漂移**：workflow 固定 `governance-gate` + audit 驗證。
- **Ruleset 漂移**：nightly audit 檢查。
- **矩陣造成 check 名稱變動**：明確禁止 matrix 命名變動。

## Dependencies
- `aaa-actions`（新增 gate workflow）
- `aaa-evals`（audit 規則）
- `aaa-tools`（verify-ci / repo-checks 既有能力）
- `aaa-tpl-docs`（SOP 與 Gate 規範）
