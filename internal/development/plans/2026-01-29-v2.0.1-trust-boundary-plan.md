# Implementation Plan: v2.0.1 Trust Boundary

## Goal Description
Build the "Trust Boundary" minimal closed-loop to enable secure agent connectivity. This version moves beyond simple logging to **Sovereign Identity** and **Scoped Enforcement**, providing the foundation for the v2.1 Bridge.

## User Review Required
> [!IMPORTANT]
> - **HMAC-SHA256 Signing**: Introducing cryptographic signatures for ledger entries. 
> - **Path-Based Scope**: Aggressive block-list; misconfiguration could lead to Agent Deadlock.
> - **Identity Rotation**: No automated rotation in v2.0.1; requires manual override.

## Triple-Summary Protocol (v2.0.1)
### 1. Strategic Plan (戰略計畫摘要)
Assign every Agent a verifiable cryptographic identity linked to their capabilities and execution scope to move from passive auditing to active enforcement.

### 2. Schema Evolution (結構演進摘要)
- `ledger_export.jsonl`: Adds `agent_id` and `signature`.
- `case_snapshot.json`: Adds `identity_proof` metadata.

### 3. Component Architecture (組件架構摘要)
Introduces a "Trust Wrapper" around kernel calls to intercept and verify agent scope before allowing I/O or governance actions.
