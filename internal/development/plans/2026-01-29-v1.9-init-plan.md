# Implementation Plan: v1.9 Supreme Court Interface

## Goal Description
Implement the **Supreme Court Interface**, a "Human-in-the-Loop" governance layer for resolving complex ethical dilemmas, edge cases, or conflicts that automated agents cannot handle.
This establishes the **"Human Sovereignty"** principle in the AAA Agent OS.

## Triple-Summary Protocol (v1.9)
### 1. Strategic Plan (戰略計畫)
-   **Objective**: Enable agents to "escalate" decisions to human supreme court.
-   **Mechanism**: `aaa court` CLI + `CaseFile` (JSON) standard.
-   **Value**: Prevents "Agent Hallucination Loops" by injecting human judgment.

### 2. Schema Evolution (結構演進)
-   **New Schema**: `CaseFile` (v1.0)
    -   `case_id`: UUID
    -   `status`: Enum(`PENDING`, `ADJUDICATED`, `DISMISSED`) **[Explicit Status]**
    -   `plaintiff`: Agent Name
    -   `facts`: Context/Logs (supports Markdown/Diff)
    -   `ruling`: Object (Verdict + Reasoning + JudgeID)
-   **Registry**: Register `supreme-court-api` and `case-file-schema`.

### 3. Component Architecture (組件架構)
-   **aaa-tools/aaa/court/**:
    -   `clerk.py`: Manages case filing, status transitions, and retrieval.
    -   `judge.py`: **Interactive TUI** logic using `rich` library.
-   **CLI**:
    -   `aaa court file`: Agent submits case.
    -   `aaa court docket`: List `PENDING` cases (Table view).
    -   `aaa court rule <id>`: **Interactive Session**
        -   Display: Formatted Facts / Diff View.
        -   Prompt: `[y] Approve / [n] Deny / [m] Modify`.

## User Review Required
> [!IMPORTANT]
> - **Blocking Workflow**: Agents *must* wait for a ruling (Spinlock/Polling).
> - **UX Priority**: The Judge's experience is critical to preventing "Alert Fatigue". The TUI must be clean and readable.
