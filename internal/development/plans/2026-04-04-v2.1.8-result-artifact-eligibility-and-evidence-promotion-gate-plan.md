## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 result artifact eligibility 與 evidence promotion gate，不允許 prose-only fallback。
2. schema 必須明確區分 `eligible` / `ineligible` result artifact，且不是所有 result 都具 promotion 資格。
3. promotion eligibility 必須由 machine-checkable gate 決定；operator narrative、manual review note、completion report 不得單獨構成 promotion 決定來源。
4. schema 必須明確區分 supporting review sources 與真正的 promotion decision source。
5. fail example 必須表達至少一個人工敘事單獨決定 promotion 的違規情形。
6. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
7. 本版目的是 runtime-plane 收斂，不構成 broader command family expansion。
8. `version_index.md` 已追加 `v2.1.8` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`。

## Out of Scope (Step1)
- 不實作 evidence promotion workflow 或 runtime validator。
- 不處理 session context snapshot 的 persistence plane。
- 不修改 `aaa-tools`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 promotion decision 退回 operator narrative 或 completion report，truth boundary 會再度人工化。
- 若未明確區分 eligibility 與 promotion，後續 runtime 很容易把所有 result 都錯誤視為 evidence candidate。

## Triple-Summary Protocol (v2.1.8)
### 1. Strategic Plan (戰略計畫摘要)
把 truth law 從 preflight 防污染推進到 result/evidence promotion 守門，避免任何 command output 自動被提升成 completion evidence。

### 2. Schema Evolution (結構演進摘要)
新增 `result-artifact-eligibility-and-evidence-promotion-gate.v0.1.schema.json`，固定 result artifact eligibility、promotion decision source 與 evidence gate 條件。

### 3. Component Architecture (組件架構摘要)
Step1 僅交付 eligibility/promotion gate bundle 與 pass/fail fixtures；Step2 若啟動，才把此 bundle 對應到 `aaa-tools` evidence promotion gate runtime。
