## Objective
建立 `v2.1.23` 的 Step1 契約基線，將 offering package level selection 收斂為固定 enum 與 selection artifact。
本版屬 `offering_package_runtime_enablement_line`；可引用 shared canonical law，但不得重新定義、覆寫或吸收 `v2.1.1` 到 `v2.1.19` 的 primary scope，也不得外溢到 definition resolution 或 prerequisite judgment；本版只定義 `lite | core | full` selection enum 與 selection artifact。

## Acceptance Criteria
1. schema 必須以 machine-checkable 方式定義 package level selection，不允許 prose-only fallback。
2. `lite | core | full` 必須在本版鎖定為 canonical enum，後續版本不得引入自由文字別名。
3. schema 必須明確定義 selection artifact，不得只靠 CLI 參數或 narrative 判定 package level。
4. 本版不得外溢到 definition resolution、prerequisite judgment、materialization、status 或 evidence。
5. fail example 必須表達至少一個自由文字別名，以及至少一個未生成 selection artifact 的違規情形。
6. 本版必須明確聲明其僅消費既有 contract，不得出現隱性 primary law 增殖。
7. `version_index.md` 已追加 `v2.1.23` Step1 row，狀態為 `UNVERIFIED` 且 `run_ref=N/A (step2-pending)`。
8. `version_index.md` 的 `status` / `run_ref` / step wording 必須使用 canonical phrase，不得出現同義改寫。

## Out of Scope (Step1)
- 本版只建立 Step1 runtime-plane baseline，不實作 runtime entry / validator / CLI wiring / frontend publish / workflow artifact。
- 不建立 offering definition resolution 或 prerequisite gate。
- 不修改 `aaa-tools`、`aaa-docs`、`aaa-tpl-frontend`、`aaa-evals` 或任何 runtime domain code。

## Risks
- 若 package level enum 未在起點固定，後續版本很容易發生 package naming 漂移。
- 若 selection artifact 不先固定，後續 resolution / gate / status 會退回自由文字與 narrative 依賴。

## Triple-Summary Protocol (v2.1.23)
### 1. Strategic Plan (戰略計畫摘要)
先把 offering package 的 level selection 鎖成 canonical enum 與 selection artifact，避免整條 package runtime 線從一開始就語義漂移。

### 2. Schema Evolution (結構演進摘要)
新增 `offering-package-selection-runtime-baseline.v0.1.schema.json`，固定 package level enum、selection artifact 與 free-text alias prohibition。

### 3. Component Architecture (組件架構摘要)
Step1 僅交付 selection bundle 與 pass/fail fixtures；Step2 若啟動，才把此 bundle 對應到 `aaa-tools` package selection runtime。
